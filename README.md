# Watermark

[![Watermark CI](https://github.com/daniil-popivanov/watermark/actions/workflows/main.yml/badge.svg)](https://github.com/daniil-popivanov/watermark/actions/workflows/main.yml)

Консольная программа на C++ для наложения водяного знака на BMP-изображение. Программа получает исходную картинку и изображение знака, смешивает их цвета и сохраняет результат в новый BMP-файл.

Проект выполнен командой из трёх студентов. В ходе работы реализованы чтение и запись бинарных изображений, смешивание пикселей, сборка через CMake и автоматические проверки через GitHub Actions. Для совместной разработки использовались Git и GitHub.

## Поддерживаемые изображения

Входные файлы должны быть корректными несжатыми 24-битными BMP с заголовком BITMAPINFOHEADER.

| Параметр | Значение |
|---|---|
| Заголовок файла | BITMAPFILEHEADER, 14 байт |
| Информационный заголовок | BITMAPINFOHEADER, 40 байт |
| Цветность | 24 бита, три байта на пиксель |
| Порядок компонентов | B, G, R |
| Сжатие | BI_RGB |
| Выравнивание строк | По границе 4 байт |

Изображение водяного знака может быть меньше исходного. Его фон участвует в смешивании цветов вместе с остальными пикселями.

## BMP-модуль

Модуль разработан студентом 1. Его объявления находятся в пространстве имён `bmpformat`.

Структура `ColorPixel` содержит поля `blue`, `green` и `red` типа `uint8_t`. Класс `BMPData` хранит ширину, высоту, глубину цвета и массив `std::vector<ColorPixel>`.

| Метод | Назначение |
|---|---|
| `Read(filename)` | Загружает изображение с диска |
| `Create(filename, ppm)` | Создаёт BMP, записывая в заголовок указанное разрешение в пикселях на метр |
| `SetParameters(width, height, bit_depth, pixels)` | Сохраняет размеры, глубину цвета и массив пикселей |
| `GetWidth()`, `GetHeight()` | Возвращают размеры изображения |
| `GetBitDepth()` | Возвращает глубину цвета |
| `GetPixels()` | Возвращает константную ссылку на массив пикселей |

Для файловых операций используются `FILE*`, `fopen`, `fread`, `fseek` и `fwrite`. Файлы открываются в бинарных режимах `rb` и `wb`.

При чтении модуль получает смещение пикселей из заголовка, считывает размеры и глубину цвета, затем загружает пиксели с учётом выравнивания строк. Для положительной высоты строки переставляются из файлового порядка bottom-up в порядок сверху вниз. Размеры в объекте сохраняются положительными.

При записи формируются заголовки и массив байтов выходного файла. Пиксели записываются снизу вверх, строки дополняются до кратности четырём байтам. Выходной путь должен иметь расширение `.bmp`.

При невозможности открыть или создать файл модуль выводит сообщение и завершает процесс через `exit`.

## Модуль наложения

Модуль разработан студентом 2 и использует `BMPData` и `ColorPixel` из BMP-модуля.

| Функция | Назначение |
|---|---|
| `BlendPixels` | Смешивает компоненты двух пикселей |
| `ApplyWatermarkToGrid` | Накладывает массив пикселей знака на массив исходного изображения |
| `ApplyWatermark` | Получает два объекта `BMPData` и сохраняет результат наложения в исходном объекте |

Цвет каждой компоненты рассчитывается по формуле

```text
result = original * (1 - alpha) + mark * alpha
```

После вычисления прибавляется `0.5` для округления, результат ограничивается диапазоном `0–255` и преобразуется в `uint8_t`. Коэффициент смешивания ограничивается диапазоном от `0` до `1`.

Основная программа использует значение `alpha = 0.35` и размещение по центру. Для знака, который помещается в исходное изображение, смещение определяется так

```text
start_x = (base_width - mark_width) / 2
start_y = (base_height - mark_height) / 2
```

Деление целочисленное. Пиксели за пределами области наложения сохраняются. На уровне функций можно передать другой коэффициент и выбрать правый нижний угол через `center = false`.

Если знак превышает размеры исходного изображения, модуль выводит предупреждение и обрабатывает доступную область. По стороне превышения начальное смещение равно нулю, выходящие за границы пиксели обрезаются.

## Основная программа

Студент 3 объединил модули в `main`, настроил CMake, тесты и CI.

Программа выполняет следующие действия.

1. Проверяет наличие трёх аргументов.
2. Загружает исходное BMP-изображение.
3. Загружает BMP с водяным знаком.
4. Вызывает `ApplyWatermark`.
5. Сохраняет результат через `Create`.

Для выходного BMP в заголовке задаётся разрешение `1000` пикселей на метр. При неверном количестве аргументов выводится подсказка. При ошибке наложения программа завершает работу, сообщения о файловых ошибках формирует BMP-модуль.

## Сборка

Нужны CMake версии 3.24 или новее, компилятор с поддержкой C++23 и Python версии 3.10 или новее. Тесты используют стандартную библиотеку Python и `unittest`.

Все команды выполняются из корня проекта.

### Linux и WSL

В системе должны быть доступны `g++` и Make.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Исполняемый файл находится по пути `build/bin/watermark`.

### Windows с MinGW

Добавьте `g++`, `mingw32-make` и Python в `PATH`.

```powershell
cmake -S . -B build-windows -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-windows
```

Исполняемый файл находится по пути `build-windows/bin/watermark.exe`.

Каталоги сборки содержат сгенерированные файлы CMake, библиотеку и исполняемые файлы.

## Запуск

Программа принимает пути к исходному изображению, водяному знаку и результату.

```text
watermark <input.bmp> <mark.bmp> <output.bmp>
```

| Аргумент | Содержимое |
|---|---|
| `input.bmp` | Исходное изображение |
| `mark.bmp` | Водяной знак |
| `output.bmp` | Файл для сохранения результата |

Пример для Linux или WSL

```bash
./build/bin/watermark original.bmp mark.bmp result.bmp
```

Пример для Windows

```powershell
.\build-windows\bin\watermark.exe original.bmp mark.bmp result.bmp
```

Относительные пути отсчитываются от текущего каталога терминала. Пути с пробелами заключаются в кавычки. Каталог выходного файла должен существовать. При повторном запуске существующий выходной файл перезаписывается.

## Тестирование

Тесты написаны на Python с использованием `unittest`. Они объединены в два набора CTest и содержат 10 проверок.

| Набор CTest | Файл | Количество |
|---|---|---:|
| `bmp_data` | `tests/test_bmp_data.py` | 4 |
| `watermark_cli` | `tests/test_watermark.py` | 6 |

Входные BMP для тестов создаются программно во временных каталогах.

### Проверки BMP-класса

| Тест | Сценарий |
|---|---|
| `test_minimum_1x1` | Чтение и сохранение BMP размером 1×1 с проверкой заголовков и пикселей |
| `test_valid_512x512` | Чтение и сохранение BMP размером 512×512 |
| `test_too_few_pixels` | В `SetParameters` передаются размеры 2×2 и массив из 3 пикселей, проверяется отказ |
| `test_too_many_pixels` | В `SetParameters` передаются размеры 2×2 и массив из 5 пикселей, проверяется отказ |

### Проверки всей программы

| Тест | Сценарий |
|---|---|
| `test_centered_watermark` | Белый знак 1×1 накладывается на чёрное изображение 3×3, центральный пиксель становится `(89, 89, 89)` |
| `test_colored_watermark_preserves_rows_and_channels` | Проверяются цвета, порядок строк и каналов, а также сохранность фона |
| `test_missing_arguments` | Проверяется сообщение при отсутствии аргументов |
| `test_missing_input` | Проверяется обработка отсутствующего исходного файла |
| `test_missing_watermark` | Проверяется обработка отсутствующего файла знака |
| `test_missing_output_directory` | Проверяется обработка отсутствующего каталога результата |

В сценариях ошибок запуска проверяются наличие сообщения в стандартных потоках, отсутствие аварийного завершения и отсутствие выходного BMP.

### Запуск тестов

После сборки выполните

```bash
ctest --test-dir build -C Release --output-on-failure
```

Для Windows с MinGW укажите каталог `build-windows` вместо `build`. Подробный вывод доступен с параметром `-V`. CTest показывает два запуска, а `unittest` выводит количество отдельных проверок внутри каждого набора.

## Ручная проверка

Для ручной проверки использовались фотография здания ИТМО и логотип.

| Файл | Размер | Назначение |
|---|---|---|
| `original.bmp` | 800×533 | Исходная фотография |
| `mark.bmp` | 320×108 | Чёрный логотип на белом фоне |
| `result.bmp` | 800×533 | Результат наложения |

Водяной знак располагается по центру с начальной координатой `(240, 212)`. На результате видны логотип и исходная фотография. Положение знака, ориентация и смешивание цветов проверяются открытием BMP в просмотрщике.

Для повторения примера разместите входные файлы в каталоге `watermark-manual` рядом с папкой проекта и выполните

```bash
./build/bin/watermark ../watermark-manual/original.bmp ../watermark-manual/mark.bmp ../watermark-manual/result.bmp
```

## GitHub Actions

Workflow `Watermark CI` расположен в `.github/workflows/main.yml`. Он запускается при `push`, при Pull Request в `main` и вручную через Actions.

| Задание | Что выполняется |
|---|---|
| `lint` | Проверка синтаксиса Python через `compileall` |
| `test_ubuntu` | Сборка и CTest на `ubuntu-latest` |
| `test_windows` | Сборка и CTest на `windows-latest` |

Задания для обеих ОС выполняются после `lint`. В них устанавливается Python 3.13 и запускаются команды

```bash
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure --no-tests=error
```

Результаты сборки и тестирования доступны на [странице GitHub Actions](https://github.com/daniil-popivanov/watermark/actions).
